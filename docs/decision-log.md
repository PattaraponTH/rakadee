## D-01 วิธีชำระเงิน

1. ผู้ชนะกดชำระ ระบบเช็กยอดใน Mock Wallet ถ้าไม่พอปุ่มกดไม่ได้และแสดงยอดที่ขาด (ไม่มีระบบเติมเงิน)
2. หักเงินทันทีใน DB transaction เดียว สถานะการชำระเงินเป็น "รอการยืนยันการชำระเงิน" และนาฬิกา 48 ชม. หยุดนับ
3. แนบสลิปจำลองได้ (ไม่บังคับ): ยอด เวลาโอน เลขอ้างอิง ไฟล์
4. แอดมินตรวจภายใน 24 ชม.
   - อนุมัติ: ชำระเงินสำเร็จ, Escrow = held, Order = รอการจัดส่ง
   - ปฏิเสธ: คืนเงินเข้า Wallet สถานะกลับเป็น "รอการชำระเงิน" ชำระใหม่ได้ในเวลา 48 ชม. ที่เหลือ

## D-02 สถาปัตยกรรม

- **Socket.IO:** ส่งราคาปัจจุบัน เวลาสิ้นสุดที่ถูกต่อ สถานะปิดประมูล และการแจ้งเตือนในเว็บแบบ real-time
- **Scheduler (node-cron):** รันทุก 1 นาที ได้แก่ ปิดประมูล, เตือนชำระที่ 24 ชม., ยกเลิกเมื่อไม่ชำระใน 48 ชม., เตือนและเปิดสิทธิ์ยกเลิกเมื่อผู้ขายไม่ส่งใน 72 ชม., ปล่อยเงินเมื่อครบ 7 วัน, คืนสถานะบัญชีที่ครบกำหนด
- **ระยะเวลาทั้งหมด** อยู่ใน `backend/src/config/time.js` ย่อได้ผ่าน `.env` ตอนทดสอบ

## D-04 ชนะแล้วไม่จ่าย

ครบ 48 ชม. โดยไม่ชำระ (ทั้งประมูลปกติและ Buy Now): Order = ยกเลิก, Payment = หมดเวลาชำระเงิน, ผู้ซื้อโดนบทลงโทษ (ครั้งที่ 2 = `suspended` 7 วัน), รายการประมูลคงสถานะ "สิ้นสุดการประมูล" ไม่เปิดกลับ, ไม่เสนอผู้บิดอันดับรอง ผู้ขายลงรายการใหม่ได้โดยไม่ถูกหักค่าธรรมเนียม

## D-05 เครดิตแรกเข้า

10,000 บาท ให้ครั้งเดียวเมื่อบัญชีเป็น `active` ครั้งแรก

## D-07 สิทธิ์สมาชิกและผู้ขาย

- สมัคร → ยืนยัน OTP → บัญชี `active` + ได้ Wallet 10,000 บาท + บิดได้ทันที (`role = bidder`)
- สมัครด้วยอีเมล + username และ login ด้วยอีเมลหรือ username ตามข้อ 2.3 เบอร์โทรใช้รับ OTP และเช็กซ้ำ
- ยืนยันอีเมลด้วยลิงก์ (ข้อ 2-5) แต่ไม่บังคับก่อนบิด
- เปิดสิทธิ์ผู้ขาย: กรอกชื่อร้าน รายละเอียด จังหวัดต้นทาง แล้ว `role = seller` ทันที ผู้ขายทำได้ทุกอย่างที่ผู้ซื้อทำได้
- ไม่มี KYC/อัปโหลดรูปบัตร และไม่มีการอนุมัติร้านค้า (requirement ไม่ได้กำหนด) เลขบัตรกรอกตอนสมัครและเก็บแบบเข้ารหัส
- `admin` / `super_admin` สร้างจาก seed เท่านั้น บิดและลงสินค้าไม่ได้ ไม่มี Wallet
- สิทธิ์ตามสถานะบัญชีใช้ตาราง D-03

## D-08 สถานะระหว่างข้อพิพาทและการจัดส่ง

- เปิดข้อพิพาทแล้ว Order = `disputed`, Escrow ยังเป็น `held` แต่ `escrow.release()` ต้องปฏิเสธเมื่อ `dispute.isOpen(orderId)` และ Scheduler autoRelease ต้องข้าม
- ไม่มีสถานะ "ถึงปลายทาง" จากขนส่ง (ไม่เชื่อม API ขนส่ง) Order เดิน `shipped` → `completed` เมื่อผู้ซื้อกดยืนยันรับหรือครบ 7 วัน
- ผู้ขายไม่ส่งเกิน 72 ชม.: ผู้ซื้อกด "ขอยกเลิก" ได้ → Order `cancelled` (`seller_no_shipment`) + `escrow.refund()` + `penalty.add(seller, 'no_shipment')`
- คืนสินค้า (`return_in_progress`) เป็นแค่สถานะของข้อพิพาท แอดมินประสานนอกระบบ ไม่มีการบันทึกพัสดุขากลับ

## D-09 ตัดออกจากสโคป

- **เติมเงิน / ถอนเงิน:** ไม่มี ผู้ขายดูยอดรายได้ใน Wallet ได้อย่างเดียว (ข้อ 1.3 "ถอนเงินหรือดูยอด")
- **KYC / รูปบัตร / เซลฟี่ / อนุมัติร้าน:** ไม่มี (D-07)
- **รีวิวและให้คะแนน:** requirement เขียนว่า "ถ้ามีในขอบเขตเพิ่มเติม" ทำเป็นงานเสริมหลัง Phase 3 ถ้าเหลือเวลา
- **ตั้งเวลาเริ่มประมูลล่วงหน้า (SCHEDULED):** ไม่มี ประมูลเริ่มทันทีที่แอดมินอนุมัติ (ข้อ 3.4-5)
- **บัญชีธนาคารของผู้ขาย:** ไม่เก็บ เพราะเงินอยู่ใน Mock Wallet ทั้งหมด
- **ฟิลด์ franchise_name / is_official / is_blind_box และระบบข้อความในข้อพิพาท:** ไม่มีใน requirement

## D-10 เส้นทางเงิน

| ขั้นตอน | ผู้ซื้อ Wallet | ผู้ขาย Wallet | สถานะเงิน |
| --- | --- | --- | --- |
| ผู้ซื้อกดชำระ | −total (`payment`) | | payment `pending_review` |
| แอดมินปฏิเสธ | +total (`payment_refund`) | | payment `rejected` |
| แอดมินอนุมัติ | | | escrow `held` = total |
| ปล่อยเงิน (ยืนยันรับ / 7 วัน / ผู้ขายชนะข้อพิพาท) | | +(total − fee) (`sale_proceeds`) | escrow `released`, fee เก็บที่ `escrows.fee_amount` |
| คืนเงิน (ผู้ขายไม่ส่ง / ผู้ซื้อชนะข้อพิพาท) | +total (`escrow_refund`) | | escrow `refunded` |

- total = ราคาปิดประมูล + ค่าส่ง; fee = `min(max(ราคาปิด × 5%, 20), ราคาปิด)` คิดจากราคาปิดเท่านั้น ค่าส่งเข้าผู้ขายเต็มจำนวน
- ทุกขั้นที่แตะเงินทำใน transaction เดียวและเขียน `wallet_transactions` ทุกครั้ง
- ตรวจยอดทั้งระบบ (QA ใช้): ผลรวม Wallet ทุกคน + payment ที่ `pending_review` + escrow ที่ `held` + fee ที่เก็บแล้ว = ผลรวมเครดิตแรกเข้า

## D-11 รูปแบบ API

- Base path `/api` (ไม่มี `/v1`) resource ใช้ชื่อตาม ERD เช่น `/api/listings` ไม่ใช่ `/auctions`
- สำเร็จ `{ "success": true, "data": ... }` ผิดพลาด `{ "success": false, "error": { "code", "message", "details"? } }` ตาม `backend/src/utils/response.js`
- Error code `UPPER_SNAKE_CASE` ไม่มี `ERR_` นำหน้า validation error ใช้ `VALIDATION_ERROR` + `details: { field: "ข้อความ" }`
- รายการแบบแบ่งหน้า: query `page` (เริ่ม 1), `limit` (สูงสุด 50) ตอบ `data: { items, page, limit, total }`
- เงินใน JSON เป็นตัวเลขทศนิยม 2 ตำแหน่ง เวลาเป็น ISO 8601 UTC
- รายละเอียดอยู่ใน `docs/api-spec/api-spec.md`

## D-12 รูปแบบข้อมูลและการยืนยันตัวตน

- id ทุกตารางเป็น `BIGINT UNSIGNED AUTO_INCREMENT` (ไม่ใช้ UUID ผสม)
- รหัสผ่าน hash ด้วย scrypt ของ Node (`backend/src/utils/password.js`) ไม่ต้องติดตั้ง package เพิ่ม
- Login ได้ session token แบบสุ่ม ส่งเป็น `Authorization: Bearer <token>` เก็บ hash ในตาราง `sessions` อายุ 7 วัน ทำให้ดูรายการอุปกรณ์และยกเลิกทุก session ตอนเปลี่ยนรหัสได้ตรงๆ (ไม่ต้องมี refresh token)
- เลขบัตรประชาชน: เก็บแบบเข้ารหัส AES-256-GCM + HMAC hash สำหรับเช็กซ้ำ/blacklist + 4 ตัวท้ายสำหรับแสดงผล คีย์อยู่ใน `.env`
